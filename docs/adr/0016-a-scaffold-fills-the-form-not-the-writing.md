# 0016. 뼈대는 서식을 채우고 글은 채우지 않는다

`engsys docs new` 가 유형의 metadata, 파일명, 필수 절 제목을 만든다. 절의 내용은 만들지 않으며,
그래서 생성 직후의 파일은 구조 검사를 통과하지 않는다. 함께 필수 절이 비었는지 검사하지 않던
결함도 고친다.

## 결정

- `engsys docs new --type <type> <slug>` 이 배정된 경로에 문서 뼈대를 만든다. 배정이 없으면
  `--path` 를 요구한다.
- 유형 계약에 `heading` 과 `filename` 을 둔다. `pattern` 은 검사용 정규식이고 `heading` 은 생성용
  문자열이다. 정규식으로 제목을 만들 수는 없다.
- 파일명은 유형이 정한다. `numbered` 는 그 디렉토리의 다음 번호를, `dated` 는 오늘 날짜를 붙이고,
  나머지는 slug 를 그대로 쓴다.
- 필수 frontmatter 는 아는 것만 채운다. `type` 과 `status` 는 계약에서, 날짜 계열은 오늘 날짜로
  채우고, 나머지는 `TODO` 로 둔다. 값을 지어내지 않는다.
- 절은 제목만 만든다. 생성 결과에 그것을 적고, 채운 뒤 `engsys docs check` 로 확인하라고 안내한다.
- `engsys docs check` 가 필수 절의 내용이 비었으면 실패한다. `frozen-status` 기록도 내용은 본다.

## 배경과 제약

문서 하나를 시작하려면 유형을 고르고, 번호를 확인하고, frontmatter 를 적고, 필수 절 제목을 계약에서
옮겨 적어야 했다. 이 저장소의 ADR 열여섯 편을 그렇게 만들었다.

이 작업을 없애다 결함이 하나 드러났다. `engsys docs check` 는 필수 절의 **존재**만 보고 내용이
비었는지는 보지 않았다. 빈 뼈대가 그대로 검사를 통과했다.
[design 0002](../design/0002-document-authoring-contracts.md) 는 "빈 필수 내용" 을 실패 조건으로
두었는데 구현에 빠져 있었다.

## 근거와 대안

- **뼈대가 예시 문장을 채운다**: 시작이 빨라 보이지만 지우지 않은 예시가 그대로 남는다. 빈 절은
  검사가 잡지만 그럴듯한 예시 문장은 아무도 잡지 못한다.
- **`heading` 없이 `pattern` 에서 제목을 만든다**: `결정|채택|Decision` 에서 제목을 고를 수 없다.
  검사용 정규식과 생성용 문자열은 다른 값이다.
- **번호를 사람이 넣는다**: 지금까지의 방식이다. 구현하면서 `0015` 다음이 `0014` 가 되는 것을
  발견했다 — POSIX 산술이 앞의 `0` 을 8진수로 읽는다. 사람이 세는 편이 안전한 것이 아니라, 세는
  코드가 틀릴 수 있다는 뜻이다.
- **`TODO` 대신 값을 추정해 넣는다**: `criteria` 나 `target` 같은 필드를 지어내면 검사는 통과하고
  내용은 거짓이 된다. 빈 값으로 두어 작성자가 채우게 한다.

## 영향

- 문서를 시작하는 명령이 하나 생겼다. 유형·번호·metadata·제목을 옮겨 적는 일이 사라진다.
- 생성 직후의 파일은 구조 검사를 통과하지 않는다. 그것이 의도다. 뼈대는 타이핑을 줄이고 글은
  작성자가 쓴다.
- 필수 절 내용 검사가 생겨 기존 문서 중 빈 절을 가진 것이 있으면 이 revision 부터 실패한다. 이
  저장소의 배정 문서 19편에는 없었다.
- 유형마다 `heading` 과 `filename` 이 늘었다. 새 유형을 추가할 때 함께 적어야 한다.
